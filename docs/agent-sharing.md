# 运维控制 Agent 共享

平台 Agent 接入后默认不共享。启动 Agent、完成注册或通过接入审批都不自动授权普通租户使用；只有平台运维能决定是否共享。开关保存在控制面，不由 Agent 本机 YAML 或自报标签决定。商户自有的 `tnode.` 节点继续只服务其所有者。

## 操作入口

- **添加 Agent**：运维「Agent 接入」页面提供「共享给所有租户」复选框，默认不勾选。生成安装命令或 ZIP 接入包时保存该选项。
- **审批 Agent**：运维「机群与审批」的审批确认框可以选择是否共享；没有先前配置的新节点默认不勾选。审批已有明确共享设置的节点时，页面带入其当前选择。
- **机群页直接控制**：在 `/operator/fleet` 每个平台注册节点的操作行点击「开启共享」或「停止共享」，确认后保存并刷新共享状态。开启专属节点共享会提示替换现有租户绑定；当前策略读取失败时不能操作。商户自有节点不提供共享按钮。
- **完整访问方式修改**：进入「Agent 共享设置」（`/operator/node-access`，也可从机群页进入），选择 Agent 的「访问方式」并保存。

| 访问方式 | 生效范围 |
| --- | --- |
| 不共享 `private` | 普通租户看不到、不能调用。有效的账号购买权益仍只开放对应运行时 |
| 共享 `shared` | 所有租户可按其现有模型授权、配额和计费规则使用；已售账号继续由购买权益隔离 |
| 指定租户 `dedicated` | 只允许所选租户；购买权益不会绕过其他租户的专属绑定 |

未配置访问方式的已有平台 Agent 也按不共享处理。已有专属绑定会保留。需要继续提供共享服务的 Agent，须由运维明确设置为共享。停用和维护仍有独立作用；允许共享不等于节点已上线、CLI 已登录或额度可用。

非共享 Agent 可以在运维计费页的「账号现货」上架 Claude Code / Codex 账号。商品上架不开放整台 Agent，只有购买者可在有效期内使用该商品绑定的运行时，不能借用同机其他账号。到期后关闭账号访问，详见[账号独享包月](billing-accounts.md)。

## HTTP 契约

所有写入要求平台运维会话；租户会话和 Agent 不能修改共享状态。

- `POST /operator/v1/agent-enrollment` 与 `POST /operator/v1/agent-install-codes` 新增可选布尔字段 `shared`，缺省为 `false`。
- `POST /operator/v1/nodes/:id/approve` 请求体为 `{"shared": false}` 或 `{"shared": true}`；旧请求 `{}` 按不共享处理。商户自有节点仍保持所有者隔离。
- `GET /operator/v1/node-access` 返回全部显式配置：`{items: [{node_id, mode, tenants, updated_by, updated_at}]}`。清单里没有的节点默认不共享。
- `PUT /operator/v1/node-access/:node_id` 整体替换访问方式和租户列表：

```json
{"mode":"private","tenants":[]}
```

`shared`、`private` 要求空租户列表；`dedicated` 要求非空列表且租户存在。未知模式、混用模式与列表、缺少或为 `null` 的 `tenants` 均返回 `400`。兼容旧客户端：省略 `mode` 时，非空列表表示专属，空数组表示显式开启共享。商户自有节点拒绝写入（`409`）。全部显式配置合计上限 1000 条，单节点最多绑定 64 个租户，写入请求上限 16 KiB。

共享设置写入后记录 `node_access.update` 审计，详情为模式和租户数量，不含凭据。通过原有 generation 通知使控制面和 Gateway 授权缓存失效；传播是最终一致，不中断已开始的工作。模型目录、候选选择、重试、固定运行时的新请求和工具续接执行同一授权组合；已提交任务的读取、取消和产物访问沿用原有租户归属保护。

## 升级与验证

基础迁移 `0015_node_sharing.sql` 给 `node_access` 增加 `mode`；已有记录默认为 `dedicated`，保留原绑定。`private` 和 `shared` 均保存显式行，空或损坏的旧专属记录仍拒绝读取，不按共享放开。

Key 校验下发 `nodes: {default_deny: true, allowed?: [...], excluded?: [...]}`。Gateway 将此授权与账号绝对到期时间共同判断。控制面不会复用缺少默认拒绝规则的旧 Redis 校验结果。

**先升级全部 Gateway，再迁移和升级控制面，最后更新 Console。** 旧 Gateway 忽略新增字段，不能执行默认不共享。新版 Gateway 对接旧控制面时保持旧策略；无控制面的独立 Gateway 不受本功能管理。生产升级仍须先备份并执行版本迁移。

默认测试覆盖新 Agent 不共享、显式共享和专属绑定、租户禁止修改、同机两个已购账号分别访问、到期与固定请求拒绝以及租户模型目录过滤。浏览器覆盖添加、审批、共享状态切换、账号购买及运维宽窄屏页面；隔离 MySQL 验证新迁移、模式 upsert 与账号事务。PostgreSQL live 与真实上游 CLI 联调尚未验收。

本地 Docker 已重建 Gateway、控制面和 Console，并完成运维及租户真实登录检查：已连接的 1 台 Agent 未显式共享时，租户模型目录不包含其服务；共享设置 API 正常，租户不能经 Console 转发修改共享状态。该检查没有调用真实上游生成，也不代表生产环境验收。

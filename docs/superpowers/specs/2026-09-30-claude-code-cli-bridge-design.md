# Claude Code CLI 经 Agent 接入 Gateway：设计与可行性门槛

日期：2026-09-30。

状态：待维护者审阅。已确认目标及“先验证 CLI 工具往返、通过后接入”的范围；本文不是已实现说明，也不代表桥接已验证可用。本次仅编写设计文档及 Agent README 中的设计入口。

## 一、已确认的目标

Agent 所在机器已经通过 `claude` 登录 Claude 订阅。其他用户在自己的电脑运行原版 Claude Code，通过 AIServeWeave Gateway 调用该节点的 Claude 能力。读文件、修改代码、运行命令及 MCP 工具执行都发生在调用者电脑上。

```text
用户电脑：Claude Code + 本地工具与项目
    ↕ Anthropic Messages / SSE
Gateway：验证用户 Key、配额、选择节点、关联工具续接
    ↕ Agent 主动建立的 mTLS 语义隧道
Agent：本地声明的 CLI 桥接实例、进程与会话管理
    ↕ stdin / stdout，以及受控的本地工具桥接通道
已登录的 Claude Code CLI → Claude 服务
```

完成标准是至少两个独立用户能完成“提出编程任务 → 模型要求工具 → 各自电脑执行 → 返回工具结果 → 模型继续”的完整流程，身份、消息、工具结果不串线。单次文本回复、模拟 SSE 或绕过工具调用均不满足目标。

## 二、当前证据与缺口

2026-09-30 对工作区及本机程序进行了只读检查：

| 项目 | 当前事实 | 对接入的影响 |
| --- | --- | --- |
| Agent 后端工厂 | `main.go:newRegistry` 注册 Ollama、vLLM、SGLang、ComfyUI | 没有现成的 Claude CLI 运行时 |
| 本地 YAML | `agentconfig.RuntimeConfig` 只有 `id`、`kind`、`base_url` | 不适合直接承载进程路径、会话限额和认证配置目录 |
| Gateway 前门 | `httpapi/anthropic.go` 已实现 `/v1/messages`、工具调用及 SSE | 可复用入口，但不能据此宣称兼容完整 Claude Code |
| Messages 转换 | `thinking` 内容块被拒绝；请求结构不建模 `thinking`、`output_config`；默认 JSON 解码不拒绝未知字段 | 存在明确拒绝和静默丢失两类兼容问题 |
| 共享模型 | `common/runtime` 与 proto 分别表达文本/多模态、工具和三项 token 用量 | 不具备完整 Anthropic 内容块、缓存用量或 CLI 会话续接语义 |
| 身份 | HTTP 鉴权身份有 `TenantID` 与 `KeyID`；`RequestHeaders.trace` 是跟踪元数据 | 跟踪字段不能直接充当会话授权契约 |
| 并发 | `runtime.Limiter` 满额直接返回背压，不排队 | 可复用请求额度；等待用户执行工具的驻留进程还要独立限制 |
| CLI | 本机报告版本 `2.1.285`；直接读取实际可执行文件的 `--help` 成功 | 仅证明安装及参数存在，不证明认证、模型请求或桥接成功 |

本机帮助列出了 `--input-format stream-json`、`--output-format stream-json`、`--include-partial-messages`、`--tools`、`--strict-mcp-config`、`--restricted` 及 `--no-session-persistence`。这些参数组合能否满足本设计必须实测，不能根据帮助文本推定可用。

`--bare` 明确不读取 OAuth 和系统钥匙串，不能作为本项目订阅登录方案的启动模式。上一次通过 shell 包装函数查询版本时出现钥匙串解锁报错；直接执行 CLI 的 `--help` 无此报错，但也不会验证登录。验证程序应直接调用已配置的可执行文件，不调用交互 shell 包装函数。

尚未执行任何真实模型请求，也未读取、导出或改写登录凭据。

## 三、方案选择

| 方案 | 是否符合目标 | 处理决定 |
| --- | --- | --- |
| CLI 文本包装：每个请求运行一次 `claude -p` 并转发回复 | 只能证明文本调用；工具可能在 Agent 执行，且不能证明历史和调用方工具语义保留 | 不作为实现方案 |
| CLI 工具桥接：把调用方工具呈现给 CLI，在用户电脑执行后将结果送回 CLI | 与用户目标相符，但进程控制、历史续接和事件边界尚未验证 | 选择此方向，先完成第四节实验 |
| Agent 直接调用 Anthropic Messages API | 接口更直接，但改变“使用本机已登录 CLI 订阅”的来源 | 不作为自动替代方案；只有用户另行改变目标才考虑 |

不从登录缓存提取 OAuth token 自行构造上游请求，不修改 CLI 二进制，不把全量 Messages JSON 拼成提示词后声称完成协议适配。CLI 仍自行管理上游认证。

## 四、第一阶段：可行性实验的完整范围

### 4.1 实验位置与隔离

获批后的第一份实施计划只覆盖独立实验，候选位置为 `experiments/claude-code-bridge/`。实验默认用假子进程和测试工具，不注册生产 runtime、不修改现有前门或 proto、不加入 Agent 正常启动路径。

真实实验采用显式 live 开关、指定 CLI 路径与模型；一次最多两个会话，不进行压力或吞吐测试。模型请求会使用既有订阅额度，记录调用数及可获取的用量，不声称客户端估计值是官方计费结果。

用临时工作目录和专用测试文件验证位置边界，不把仓库源码或用户工作文件作为测试素材。CLI 登录由其原生机制读取；实验不替用户登录、刷新凭据或修改 shell/钥匙串。认证失败时输出脱敏错误并停止 live 测试，离线测试仍可运行。

### 4.2 候选桥接机制及必须回答的问题

优先验证公开支持的 MCP 工具接口与 CLI JSON 流：

1. 把调用方声明的一个测试工具注册为 CLI 可调用的桥接工具；关闭 CLI 自带执行工具及无关扩展。
2. CLI 发出工具请求时，桥接层仅记录关联并等待远端结果，不执行传入参数。
3. 对调用方输出一个完整的 Messages 工具调用响应，让调用方能够结束当前 HTTP 请求并运行本地工具。
4. 调用方在后续请求中返回 `tool_result`，桥接层将其投递到正确的待决调用；观察 CLI 是否继续产生回复。
5. 验证 CLI 对外事件能否明确划分一次模型回合、工具请求集合和结束状态，尤其是并行工具。不能用“等一小段时间没输出”判断回合完成。

MCP 名称可能带服务名前缀，必须维护工具名及调用 ID 的双向映射，并检查 JSON Schema、参数与错误结果是否保真。MCP 名称转换本身不等于 Anthropic 工具协议透明转发。

如果公开 CLI 输入/输出或 MCP 接口无法提供可靠的回合边界、返回工具结果入口或受控执行边界，实验直接判定不通过。不得通过解析终端文字、伪造工具结果、使用未验证的隐藏控制协议等方式绕过门槛。

### 4.3 验收矩阵

| 编号 | 场景 | 必须观察到的证据 |
| --- | --- | --- |
| V01 | 已登录 CLI 产生流式回复 | 真实 JSON 事件及成功结果；认证失败不得标记通过 |
| V02 | 自定义工具单次往返 | CLI 提出的参数到达调用方；调用方的确定性结果进入同一推理流程 |
| V03 | 工具执行位置 | 测试文件只出现在调用方工作目录；Agent 目录无副作用；禁用的本地执行入口被拒绝 |
| V04 | 连续及并行工具 | 至少两轮工具往返；同轮两个工具乱序返回仍正确关联；SSE 不重复、不乱序 |
| V05 | 两个用户同时调用 | 同名工具、不同结果不串线；伪造其他用户关联 ID 被拒绝 |
| V06 | 断开、取消与退出 | 生成中取消和等待工具超时能释放子进程、管道、会话和额度 |
| V07 | 重试及历史 | 重复工具结果不重复推进；修改历史、模型或工具集合不会错误续接旧进程 |
| V08 | 原版客户端 | 无客户端代码修改，完成一次读取专用测试文件及修改专用测试文件的编程流程 |
| V09 | 扩展兼容 | 记录客户端实际请求的 thinking、缓存、工具扩展及模型参数，逐项证明支持或返回明确的不支持错误 |

V01–V09 全部有证据且不存在阻止 V08 的兼容缺口，才能进入生产接入设计定稿。某项只能用假进程通过、真实测试跳过或未运行，都不算通过。

实验报告必须区分离线通过、真实通过、失败和未运行，保存版本、脱敏配置、执行命令、退出码及结构化事件摘要。测试 Prompt 和合成工具内容可以作为明确标记的测试 fixture；真实用户消息、认证数据、完整运行日志不得混入报告。

## 五、第二阶段架构约束（实验通过后才定稿实施接口）

本节确定职责及验收约束，不提前承诺 CLI 具有第四节尚未验证的能力。实验报告是后续生产实施计划的输入；本次审批不等于允许跳过实验直接修改公共契约。

### 5.1 Agent 本地进程管理

拟在 Agent 内新增 `claudecode/` 包，进程实现只由 Agent 装配；Gateway 不启动 CLI。优先使用 Go 标准库 `os/exec` 和 JSON 编解码，不增加 Node/Python SDK 到 Agent 的部署依赖。

可执行文件、固定启动策略、认证配置目录、可用模型、进程上限和超时均由 Agent 本地配置决定。Gateway 只能指定已发布的运行时/模型及推理语义，不能提供命令、CLI 参数、工作目录、环境变量或 MCP 服务地址。CLI 配置不能伪装为 `base_url`。

CLI 自带 Bash、文件工具、浏览器、自动加载插件、Hooks、项目指令和其他 MCP 不能成为用户 Prompt 获得 Agent 本机权限的入口。`--restricted`、`--tools ""` 和严格 MCP 配置只是候选机制，组合是否生效由 V03 验证；`--safe-mode` 也不能未经验证与所需桥接 MCP 混用。子进程不继承指向本 Gateway 的客户端认证/地址覆盖，避免代理递归。

每个活动会话使用独立 CLI 进程和独立临时工作目录。关闭会话需终止并回收完整进程树、桥接端点和管道。会话不使用 `--continue` 的“最近一次”选择方式。若选择 `--no-session-persistence`，进程退出后会话即失效，不能再声称支持 `--resume` 恢复。

### 5.2 有状态续接与调度

CLI 可能在首次 HTTP 请求结束后仍等待客户端工具结果。此时普通请求 context 和隧道流槽已经结束，CLI 生命周期必须由有界会话管理器持有，不能把“返回 tool_use”当成用户取消。

会话至少区分：创建、生成、等待工具、继续生成、结束、失效。生成阶段客户端断开则取消本轮；已完整返回工具回合后进入等待工具状态，使用独立超时。

每个后续 HTTP 请求重新验证 Gateway Key。会话归属使用已认证的 `(TenantID, KeyID)`，不信任请求体的用户标识或任意 trace 字段。同一个 Key 并发会话仍需独立的服务端生成关联标识，不能只用租户或 Prompt 摘要当作会话 ID。

Messages 没有可依赖的通用续接 Cookie。候选关联方式是在服务端发出的 `tool_use.id` 上建立不透明映射，客户端会在 `tool_result` 中回传；它不是认证凭据，仍需身份、历史和待决状态校验。工具调用映射能否在原版客户端保留由 V08 确认。无工具续接的普通新轮次不能假定携带该标识，需单独验证重建历史或会话定位策略。

续接必须定位原 Agent/runtime，不能进入普通随机选择或失败重试到另一节点。多 Gateway 副本需要共享映射及原子续接仲裁；拟复用 Gateway 已允许的 Redis，Redis 不可用时拒绝有状态续接，不能回退到各副本各自创建会话。单副本内存实现可以用于实验，不能标成跨副本可用。

验证重复请求、重复结果、过期映射、服务重启和隧道中断。首版不承诺跨 Agent 重启恢复；会话失效明确报错，不将历史或工具结果投给新进程“猜测续跑”。禁止在已产生模型输出或已接收工具结果后进行不受控重放。

### 5.3 资源边界

区分 HTTP 在途请求额度、CLI 活动进程额度与等待工具会话额度。最后一项在首个 HTTP 响应结束后仍占资源，不能只复用 `runtime.Limiter` 便视为已限流。

实验固定两个最大活动会话、每会话一个在途模型回合、最多八个待决工具、工具等待最长两分钟、会话总寿命最长十分钟；超限直接拒绝或终止，不设置无界等待队列。每个 JSON 事件最多 1 MiB，每次请求最多 8 MiB，每次工具结果最多 1 MiB；达到上限显式失败。这些是实验预算，不是现有生产配置默认值。

生产数值在实测事件尺寸与工具耗时后单独定稿，但有限上限是必需条件。文本、参数增量和产物逐段传递，CLI stdout/stderr 不能通过 `CombinedOutput` 无界累计。读取 stdout 必须受下游背压约束；stderr 的有界处理不能泄漏 Prompt 或凭据。

### 5.4 共享契约与协议兼容

若实验通过，需要明确的后端能力标识和经过验证的配置类型。执行身份、会话关联和续接控制应建模为契约字段，不滥用 `Extra` 或 `trace` 隐藏授权数据。

所有新增隧道字段从 `api/proto/tunnel/v1/tunnel.proto` 生成，转换只落在 `common/tunnelwire`。共享 Go 契约放在 `common/runtime` 或经评审确定的专门共享包，不能在 Agent/Gateway 各定义一份等价结构。

保持语义隧道：不传任意 HTTP 方法、URL、Host、Authorization 或本机登录 token。需要的协议版本/能力应以受校验的明确语义字段表达，不新增通用头透传 map。

CLI 重新组织 system、tools 或历史时，不能声称保留 Anthropic 原始 thinking 签名及缓存语义。对 thinking 内容、工具 ID、块顺序、停止原因和用量字段逐项验证；无法支持的字段明确报错，不能静默删除后标记请求成功。支持受限客户端配置时必须公开具体配置与功能差异，并在 V08 实测。

`count_tokens` 可以独立作为后续功能，不能返回伪精确计数。订阅限额仍由上游执行，Gateway 本地配额并不会增加订阅额度。每轮用量和累计用量必须区分，避免把 CLI 累计结果重复计入多个用户请求。

## 七、测试、交付与退出条件

默认测试不访问模型服务或真实订阅；使用假 CLI、假 MCP 工具及注入的 `runtime.Clock`。不以真实 `time.Sleep` 驱动超时测试。进程退出、流式错误、超限、取消及授权失败必须有行为测试；协程泄漏统一在包 `TestMain` 检查。

真实联调单独门控，必须覆盖 V01–V09，并对每个声称支持的 CLI 版本留证据。先使用合成工具证明位置边界，再用隔离工作目录中的原版客户端完成真实工具往返。

生产阶段仍执行仓库完整门禁：gofmt、vet、build、proto generate 一致性、全量单测与服务 race 测试。全量绿灯不能代替真实 CLI 联调成功。增加 Go 代码时遵守双语注释和表驱动测试约定，并完成 Go 代码审查。

实验失败时交付失败点、最小复现、版本和已通过项，停止生产契约改造；不自动将目标替换为纯聊天、在 Agent 执行用户工具或直连 API Key。后续是否改变需求由维护者决定。

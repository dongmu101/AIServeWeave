# P02 Routing Management Implementation Plan

**Goal:** ControlPlane immutable route revisions, CAS publish/rollback, Gateway bounded pull/atomic activation/last-good cache, live per-Gateway verification, Console C24 editor/import/compare/publish/rollback.
**Architecture:** Platform-wide route bundle. Editable draft stays local until publish. No new tenant/node authorization semantics. Explicit file vs controlplane source. Shared contract in common/modelroute; no ORM/database driver in Gateway.
**Spec:** User-approved five-part design in this conversation, 2026-09-08.

## Shared contract and interfaces

`modelroute.Target` and `Route` preserve existing routing JSON. `Validate(routes []Route) error`, `Digest(routes []Route) (string,error)` use deterministic canonical JSON and reject duplicate aliases/negative weight/empty models, count and byte limits. `MaxRoutesBytes=1<<20`, `MaxDocumentBytes=MaxRoutesBytes+64*1024`, `MaxRoutes=1000`, `MaxTargets=100`, `MaxRevisions=1000`. Errors do not echo payloads.

`RevisionInfo`: revision int64, digest string, created_at timestamp, actor_id string, rollback_of int64 omitted when zero. `Snapshot`: embedded RevisionInfo plus routes []Route. Zero revision means unpublished. `Applied`: mode (file/controlplane), revision, digest, applied_at, checked_at, error (fixed code). Gateway admin adds replica_id and generated_at through `ReplicaStatus` embedding Applied.

ControlPlane routes (platform-session only):
- GET /operator/v1/routes -> Snapshot (revision 0 + empty routes before first publish)
- POST /operator/v1/routes/validate {routes} -> {valid:true,digest}
- POST /operator/v1/routes/publish {expected_revision,routes} -> Snapshot, 201; stale expected revision 409.
- POST /operator/v1/routes/rollback {expected_revision,revision} -> new Snapshot, 201; source immutable old version, rollback_of recorded.
- GET /operator/v1/routes/history?before=<revision>&limit=<1..50> -> {items:[]RevisionInfo,next_before?:int64}; newest first.
- GET /operator/v1/routes/revisions/:revision -> Snapshot
- GET /operator/v1/routes/status -> {desired_revision,desired_digest,checked_at,complete,replicas:[{endpoint,replica_id?,revision?,digest?,mode?,applied_at?,checked_at?,generated_at?,error?}]}. Every configured Fleet endpoint represented; no Fleet or any failure => complete false. Compare source mode, revision AND digest; no persisted stale ACK implies current confirmation.
- GET /internal/v1/routes/current -> Snapshot with InternalToken guard; 404 when no publication.

Gateway GET /internal/v1/routes -> modelroute.ReplicaStatus with admin Token. `adminapi.Config.Routes func() modelroute.Applied`. All result/error reads bounded. Polling does not overlap; clock injected; version regressions and same-revision/different-digest rejected. Snapshot is immutable and copied on input; each request sees one version. Cold managed startup loads validated cache or fetches; absent both fails startup. Config `-route-source=file|controlplane` default file, `-route-state-file`, `-route-sync-interval`; managed forbids -model-routes and requires control-plane addr/token + state file. Keep original unknown-model passthrough semantics after an explicit valid snapshot is activated.

## Rulings

Shared checkout initially clean; independent workers own disjoint services while root owns common/modelroute and fleet status aggregation. No commits or pushes. All revised/new comments bilingual. Route publication history capped at MaxRevisions (explicit capacity error), pages bounded; no silent historical deletion. Existing file JSON can be imported from Console, each file/bundle subject to same limits. Rollback never decrements version. Schema migrations opt in via existing AutoMigrate deployment setting, with dedicated route migration tracking.

# 按 token 计价（官方价 × 倍率）

点数计费下，每次请求的费用按「官方价目表 × 倍率」计算，参照 [sub2api](https://github.com/Wei-Shaw/sub2api) 的做法。本文说明计价规则、运维要做的设置，以及升级步骤。设计取舍见 `.scratch/token-pricing/spec.md`。

1 点 = 1 美元。官方价 $3 / 百万输入 token，就是 3 点 / 百万 token。余额、账目与费用内部都以 micro 点存储（1 点 = 1,000,000 micro）。

## 计价规则

### 售价

```
售价 = 基础价 × 模型倍率 × 方案系数
```

或者，租户所属方案为这个别名设置了**固定售价**时，直接按固定售价收费，不再乘以任何倍率。

**基础价**按顺序取第一个存在的：

1. **覆盖价**：运维为这个别名填写的单价表。它整张替换官方价，表里没填的计量项按下文的查找顺序回落，不再去价目表里找。
2. **官方价**：价目表条目。条目名取运维为别名指定的「参照模型」；没有指定时用别名本身，名称必须**完全一致**。不做模糊匹配，以免本地模型（例如 `deepseek-r1:7b`）被当成 API 模型收费。
3. **默认价**：运维填写的默认单价表。
4. 都没有：按 0 计费，价格来源记为 `none`，Console 显示「有 N 个别名正在以 0 价计费」的提示。

**模型倍率**按别名设置，对所有租户生效，默认 1；用于「这个模型上游成本高，统一加价」。**方案系数**来自租户所属的价格方案（见下文）。倍率与系数的范围都是 0–100 倍，0 表示免费。

示例：模型 X 官方价 $3 / 百万输入 token，模型倍率 1.5；VIP 方案默认系数 0.8。VIP 租户的售价是 3 × 1.5 × 0.8 = $3.6 / 百万 token。

### 计量项

一次请求的用量分成若干「计量项」，各有单价：

| 计量项 | 含义 |
| --- | --- |
| `input` | 全部输入 token（`prompt_tokens`），包括缓存读取与写入 |
| `input.cache_read` | 命中提示缓存的输入 |
| `input.cache_write` | 写入提示缓存的输入（单价是 5 分钟缓存的价格） |
| `input.cache_write.1h` | 其中缓存 1 小时的部分 |
| `output` | 全部输出 token，包括推理 |
| `output.reasoning` | 其中用于推理的部分 |

子项是父项的一部分，每个计量项按「自身数量 − 子项数量」计费。例如输入 1000、其中缓存读取 600，则 400 按输入价、600 按缓存读取价计费。

某个计量项没有自己的单价时，**按父项的单价计费**（`input.cache_write.1h` → `input.cache_write` → `input`）。所以价目表没有缓存价时，缓存 token 就按普通输入价收，不会少收。

**长上下文档位**：价目表给了「输入超过 N token 时」的单价（例如 200k、272k 档）时，一次请求的输入总数超过 N，整次请求的各计量项都改用该档单价。

### 按请求时间计价

价目表、定价配置与租户所属方案都保留历史。每条用量按**请求发生的时间**取当时有效的价格，与它多晚入账、由哪个控制面副本入账无关。所以改价之前发出、改价之后才入账的请求，仍按旧价收费。

唯一的例外：改价在生效时刻之后片刻（一次小事务的时长）才提交，这段时间内发起、又在提交前推送的请求会按旧价计价。

### 每笔费用明细

每条用量记录都保存计价结果：原价（倍率之前）、实扣点数、总倍率、价格来源（`override` / `catalog` / `default` / `plan_fixed` / `none`），以及各计量项的数量、单价和费用。事后改价不影响已入账的记录。

- 由商户自有节点服务的请求照常计价，但不扣费。
- 由运维在机群页设为「免费」的平台节点服务的请求同样照常计价、不扣费；按扣费时的设置判断。
- 只有 prepaid 租户真正扣余额；exempt 与 account_monthly 租户照样计算、记录费用，但不扣费。
- 费用向上取整，非零用量在非零单价、非零倍率下不会是 0；超出 int64 的费用饱和为最大值。

## 运维设置

都在 Console「计费」页的运维视图里完成；所有修改都写审计。

### 模型定价

列出全部路由别名，以及已配置但没有路由的别名，显示价格来源、参照条目、各计量项的基础价、模型倍率与默认方案下的售价。

- **参照模型**：别名与价目表条目名不一致时（例如别名 `my-claude`、条目 `claude-sonnet-4-5`），搜索价目表选择参照模型。只能选价目表里存在、且未被批准删除的条目。
- **覆盖价**：可以「从官方价复制」后修改。
- **默认价**：给价目表里找不到的别名（通常是本地模型）一个兜底单价。
- 每次修改都追加一个新的配置版本；两人同时修改时，后提交的一方会收到冲突提示，刷新后重做。

### 价格方案

方案 = 默认系数 + 按别名的系数或固定售价。每个租户属于一个方案，没有指定的租户属于**默认方案**。默认方案不能删除，它的默认系数就是全局倍率。还有租户在用的方案不能删除。

在「租户」列表中为租户选择方案；修改从当前时刻起生效。

### 价目表与审核

价目表来自 LiteLLM 的 [`model_prices_and_context_window.json`](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json)。控制面内置一份快照（2026-11-16，3689 个条目），首次启动时导入；之后按 `RefreshInterval` 拉取远端并比对：

| 变动 | 处理 |
| --- | --- |
| 新条目 | 自动生效 |
| 已有条目改价，相对变动不超过 `AutoApplyMaxChangePercent` | 自动生效 |
| 改价超过阈值、降为 0、从 0 上涨、删除某个单价、新出现原本没有的计量项 | 进入待审核，期间继续用原价 |
| 上游删除条目 | 进入待审核，标记「上游已删除」，期间继续用原价；批准后条目不再可用 |

在「价目表审核」中逐条批准或拒绝；拒绝后，同一份上游内容不再提醒。只导入对话、补全、Responses 与 embedding 类条目，且输入价或输出价至少有一个大于 0。

### 未定价提示

有别名正在以 0 价计费，或者最近 24 小时出现过未定价的用量时，计费页顶部会显示提示。请为这些别名设置参照模型、覆盖价或默认价。

## 余额账目

扣费立即从余额扣除，但**不再每批写一条账目**：金额累计在租户的计费行上，到下列时机才封成一条用量账目：

1. 跨过 `Billing.LedgerTimezone` 时区的午夜之后的下一次扣费；
2. 该租户写入任何其他账目（充值、退款、争议、调整、赠送）之前；
3. 后台每分钟一次，处理已过当天、但没有新扣费的租户。

所以账目中每个租户每天通常只有一条用量记录，中途每有一笔资金事件就多切出一段。账目只追加、写入后不再修改，余额链始终成立：每条账目的余额等于上一条加上本条金额，最新一条的余额加上「进行中」的累计（负数）就是当前余额。

Console 的账目页最上面显示「进行中」一行；用量账目显示时间段与请求数，并可跳到这段时间的逐笔明细。账目按扣费时间分段，逐笔明细按请求时间筛选，两者的边缘可能差几秒。

为保证顺序，每个租户的账目时间严格递增：新账目至少比上一条晚 1 微秒，因此充值、退款等账目的时间偶尔会比实际发生时间晚几微秒。

控制面不会修改或删除 `credit_ledger` 的行，因此生产运行账号可以只授予这张表 `INSERT` 与 `SELECT` 权限；存量压缩命令（见下文）改用 `Database.MaintenanceDSN` 执行。

## 配置

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `Billing.PriceCatalog.URL` | LiteLLM 在 GitHub raw 上的地址 | 远端价目表。中国大陆常连不上 GitHub raw，可以换成镜像，或者 `https://api.github.com/repos/BerriAI/litellm/contents/model_prices_and_context_window.json`（未认证每小时限 60 次，每天同步一次足够） |
| `Billing.PriceCatalog.RefreshInterval` | `24h` | 远端同步间隔，最短 10 分钟；`0` 表示不拉远端，只用内置快照 |
| `Billing.PriceCatalog.AutoApplyMaxChangePercent` | `30` | 已有条目改价时可自动生效的最大相对变动，0–1000；`0` 表示所有改价都要审核 |
| `Billing.LedgerTimezone` | `UTC` | 用量账目日界所用的 IANA 时区，例如 `Asia/Taipei`、`Asia/Shanghai`。名称无效时拒绝启动；时区数据已内置于二进制。修改只影响之后新开的累计 |

这些配置只在 `Billing.Enabled` 时生效。示例见 `deploy/controlplane.example.yaml`。

## 升级

适用于从 2026-11-16 之前的版本升级。

### 顺序

**先控制面（与 Console 一起），再 Gateway，最后 Agent。**

- 用量推送新增 `details`、`attributes` 两个字段，旧控制面会拒绝整批，所以控制面必须先升级。之后再新增计量项，不再需要控制面先行。
- 旧 Gateway、旧 Agent 不上报缓存明细，缓存 token 按普通输入价收费，与升级前相同。
- 旧的 `/operator/v1/billing/model-prices` 已移除，旧版 Console 的「模型单价」会请求失败，所以 Console 要与控制面一起升级。

### 迁移

| 迁移 | 内容 | 锁与耗时 |
| --- | --- | --- |
| `usage_records/0005_pricing.sql` | 用量记录新增缓存与费用列、明细 JSON | 即时加列（MySQL `ALGORITHM=INSTANT`；PostgreSQL 常量默认值不重写表） |
| `usage_records/0006_tenant_created_index.sql` | 索引 `(tenant_id, created_at, id)`，供逐笔明细分页 | **不是即时完成**。MySQL 用 `ALGORITHM=INPLACE, LOCK=NONE`，不阻塞写入；PostgreSQL 在分区父表上建索引，**期间阻塞 `usage_records` 的写入**（分区父表不支持 `CONCURRENTLY`），用量入账会暂停。大表须先在恢复副本上计时，安排在低峰期 |
| `billing/0012_price_catalog.sql` | 价目表四张表 | 新建表 |
| `billing/0013_pricing_config.sql` | 定价配置版本、租户方案历史、版本号 | 新建表 |
| `billing/0014_usage_ledger.sql` | `tenant_billing` 累计字段与索引、`credit_ledger` 时段与请求数 | 小表；`credit_ledger` 加列即时完成 |

照常先备份，执行 `-migrate up`，再用 `-migrate status` 确认全部 applied。

### 行为变更

- **原本落到 `*` 默认价的别名**，只要名称与价目表条目完全一致，升级后就按官方价收费。升级后请先在「模型定价」页核对售价。
- **1 点 = 1 美元成为定价基准**。现有余额与充值包的点数不变，请按这个单位重新核对充值包的价格。
- **已有的 `model_prices` 行**在首次读取定价配置时转换成第一个配置版本：每行变成该别名的覆盖价，`*` 行变成默认价，模型倍率与默认方案系数都是 1，所以这些别名升级前后价格一致。`model_prices` 表保留但不再读写。
- **Claude CLI 桥接的用量会明显增加**：Gateway 的原生 Messages 路径原本漏计了缓存读取与写入（Messages API 的 `input_tokens` 不含缓存），升级 Gateway 后会按实际计入用量、配额与费用。Claude Code 的输入大部分是缓存读取，增幅可能很大，升级前应通知相关商户。
- **扣费防重改由 `usage_records` 承担**，`usage_charges` 不再写入。

### 不能直接回退

升级后不能直接换回旧版控制面：旧版只查 `usage_charges` 防重，升级期间入账的记录如果再被 Gateway 重发，会被重复扣费。回退必须恢复升级前的备份。

### 可选的维护命令

两个命令都可以重复执行，也可以中断后再执行，进度以 JSON 行输出；都会先检查表结构是最新的。

```sh
# 把升级前的费用从 usage_charges 写回 usage_records，使旧记录出现在费用汇总与明细里
aiserveweave-controlplane -f controlplane.yaml -migrate backfill-usage-cost

# 把升级前「每批一条」的用量账目，按 Billing.LedgerTimezone 合并为每天一条
# 会改写财务记录，执行前务必备份；设置了 Database.MaintenanceDSN 时用它执行
aiserveweave-controlplane -f controlplane.yaml -migrate compact-usage-ledger
```

不回填时，升级前的记录在 Console 显示为「升级前」，也不计入费用汇总。回填后这些记录的价格来源为 `legacy`、倍率记为 1。
